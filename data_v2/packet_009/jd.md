# Backend / Platform Engineer — Small team — hands-on breadth

## Context
Lean team with few layers, direct communication, high individual contribution, and limited redundancy.

## Must-have evidence
- production API or service ownership
- Python, Go, or Java
- distributed systems fundamentals
- hands-on implementation
- independent delivery
- clear communication

## Preferred evidence
- observability
- event-driven systems
- cloud cost awareness
- on-call ownership
- product partnership
- pragmatic trade-offs

## Interview focus
- Which deliverables did the candidate implement directly?
- Where does the record distinguish breadth from unsupported self-description?
